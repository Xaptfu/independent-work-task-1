# qc_reads
Скрипт выполняет контроль качества прочтений секвенирования: считает длину, GC-состав и среднее качество каждого прочтения, отбрасывает адаптерную последовательность, фильтрует прочтения по порогу качества и записывает очищенный FASTA, сводную таблицу TSV, гистограммы и отчёт.

## Структура

```text
qc_reads/
├── .gitignore                     # исключения git (.venv/, results/, data/raw/*.fastq)
├── README.md                      # этот файл
├── requirements.txt               # прямые зависимости
├── data/
│   ├── processed/                 # промежуточные данные (не используется)
│   │   └── .gitkeep               # хранит пустую папку в git
│   └── raw/                       # исходные FASTQ файлы (в git не хранятся)
│       └── reads_2024_04_02.fastq # входные данные (добавить вручную)
├── results/                       # создаётся программой, в git не хранится
│   ├── clean_reads.fasta          # отфильтрованные прочтения
│   ├── qc.png                     # гистограммы GC и качества
│   ├── qc_summary.tsv             # сводная таблица

│   └── main.py                    # код
└── tests/
    └── .gitkeep                   # зарезервировано под тесты
```

## Требования

- Системные утилиты не требуются.

## Входные данные

Файл FASTQ, кодировка UTF-8. Каждое прочтение занимает 4 строки: заголовок, последовательность, разделитель + и строка качества. Длина последовательности должна совпадать с длиной строки качества (иначе прочтение отбрасывается на этапе чтения).

Файл по умолчанию — data/raw/reads_2024_04_02.fastq от корня проекта. Другой файл передаётся первым аргументом, каталог результатов — вторым

Внимание!!!
Файлы FASTQ не хранятся в репозитории. Поместите ваш файл reads_2024_04_02.fastq в каталог data/raw/ перед запуском


```bash
python3 src/main.py data/raw/my_reads.fastq results/
```

## Запуск

Из корня проекта, при активированном окружении:

```bash
python3 src/main.py
```

Оба аргумента необязательны, порядок фиксирован:

```bash
python3 src/main.py data/raw/reads_2024_04_02.fastq results/
```

Первый — путь к FASTQ, второй — каталог для результатов. Если не указывать, берутся data/raw/reads_2024_04_02.fastq и results/. Второй аргумент без первого не работает.

## Выходные данные

В каталоге, указанном вторым аргументом (по умолчанию results/), появляются четыре файла:

qc.png — две гистограммы. Слева — распределение GC-состава (среднее отмечено красной линией), справа — распределение среднего качества (порог 25 отмечен красной линией). 200 dpi.

clean_reads.fasta — очищенные последовательности, прошедшие фильтр (без адаптера, длиной от 100 п.н., со средним качеством от 25).

qc_summary.tsv — таблица со статистикой по каждому прочтению: имя, длина, GC-состав, среднее качество.

report.txt — текстовый отчёт. Содержит имя файла, общее число прочтений, число прошедших фильтр, средний GC и число прочтений с N.

Каталог создаётся программой, если его нет.

## Ограничения

1. **Ошибки разбора подавлены**. В блоке расчета качества стоит except: pass. Если meanq() выбросит исключение, переменная z сохранит значение от предыдущего прочтения. Результат будет зависеть от порядка строк в файле. Статус: не исправлено.

2. **Числовые параметры заданы в коде без имён**. Длина адаптера (13), порог качества (25), минимальная длина (100) и число бинов для гистограмм (40) зашиты в код. Изменение параметров требует правок в нескольких местах. Статус: не исправлено.

3. **Глобальное состояние**. Списки STATS и SKIPPED объявлены на уровне модуля и заполняются внутри цикла. Функции read_fastq, gc, meanq зависят от этого глобального состояния, импортировать и тестировать их изолированно нельзя. Статус: не исправлено.

4. **Файлы не закрываются при исключении**. open() используется без with, поэтому при ошибке внутри блока чтения или записи дескриптор остаётся открытым. Статус: не исправлено.

5. **Неиспользуемый код**. Импорты os, math, numpy и переменная bad в коде не используются. Статус: не исправлено, на работу не влияет.
